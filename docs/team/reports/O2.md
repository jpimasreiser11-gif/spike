# O2 — One task space

Owner: Claude (the lead wrote it: the workers were on their weekly usage limit until 2026-11-16).

## Summary
A task (a Forge or multi-step chat answer, or a Dev session) shown in one place, in four parts that are always
present: the plan with each step's state, every action with the permission it got, the files it changed and what it
delivered.
- **No new storage.** The chat already kept each answer's events (`meta.events`). Dev sessions now keep them the same
  way; the rule (merge text pieces, cap 3,000, time per event) moved to `spike/core/run_record.py` and the chat uses it
  too. Everything is rebuilt from those events, so a task reopens after a restart as it ended and nothing runs again.
- **`web/src/taskSpace.ts`** (pure): `taskFromEvents` links each `permission_request` to its call by `call_id`, tells
  a call the settings allowed (`auto`) from one they blocked (`refused`, from the loop's own result texts) and from one
  never answered before the run ended (`unanswered`); a step the checker sends back stays the planned step, with its
  round; one mind's own actions in Parallel Minds are left out; the undo state comes from the stored answer, which the
  server updates after the run. `mergeTasks` joins a Dev session's turns.
- **`TaskSpace.tsx`**: the view and its dialog. In the chat, **Ver tarea** appears under a Forge or multi-step answer
  (also while it runs, and it follows it). In Dev sessions it replaces the side list; the changed-files part keeps the
  server's change list with undo and conflict handling. Full screen on a phone.
