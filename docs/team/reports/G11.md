## Resumen

Siguiendo las reglas de alcance de las Secciones 6 y 8 de incorporación (*«No modifiques motor/presupuestos (`core`) [...]
si el problema entra en núcleo, seguridad o contratos públicos, escribe un informe con reproducción mínima para que Claude
decida la corrección»*), esta entrega documenta **sin modificar código de `core/` ni `secrets.py`** dos defectos
reproducibles verificados empíricamente durante la auditoría de fiabilidad de sesiones, ventanas de contexto y modo
`-X utf8=0`:

1. **`spike/core/context.py:52` (`fit_messages`) — Mensajes `role="tool"` huérfanos enviados a proveedores cuando el turno
   de herramienta supera `budget_tokens`:**
   - El bucle `while kept and kept[0].role == "tool" and len(kept) > 1: kept.pop(0)` se detiene cuando `len(kept) == 1`.
   - **Caso 1A (herramienta única con salida grande, p. ej. `read_file` o `run_command` en contexto local 8K):**
     `for m in reversed(rest)` conserva siempre el último mensaje (`tool(c1)`) porque en la primera iteración `kept` está
     vacío (`if kept and used + cost > budget_tokens` es `False`), y rompe el bucle antes de incluir el turno
     `assistant(tool_calls=[c1])` y el `user`. Como `len(kept) == 1`, la línea 52 **no elimina** `tool(c1)` y
     `fit_messages()` devuelve `[system, system_note, Message(role="tool", tool_call_id="c1")]`, violando su propio
     contrato (*«A tool result is never kept without the assistant turn that requested it, so the provider never sees an
     orphaned tool message»*).
   - **Caso 1B (turno multi-herramienta `tool_calls=[c1, c2]`):** si caben `tool(c2)` y `tool(c1)` pero no cabe
     `assistant(tool_calls=[c1, c2])`, `kept` vale `[tool(c1), tool(c2)]`; la línea 52 hace `pop(0)` de `tool(c1)` y se
     detiene al quedar `len(kept) == 1`, dejando igualmente `tool(c2)` huérfano.
   - **Impacto directo en `run_agent` (`spike/agent/loop.py:72`):**
     - En `OpenAICompatProvider` (`llama-server`, OpenAI, Gemini OpenAI-compat, Mistral, Ollama, LM Studio), el primer
       mensaje no-`system` pasa a ser `{"role": "tool", "tool_call_id": "c1", ...}` sin `tool_calls` previo (HTTP 400).
     - En `AnthropicProvider` (`spike/providers/anthropic.py:38-39`), `to_anthropic()` genera como `messages[0]`
       `{"role": "user", "content": [{"type": "tool_result", "tool_use_id": "c1", ...}]}`, rechazado por Anthropic Messages
       API con HTTP 400 (`unexpected tool_use_id found in tool_result blocks`).
   - **Nota crítica para la corrección:** cambiar únicamente `and len(kept) > 1` por `while kept and kept[0].role == "tool":`
     **no basta**, porque en el paso activo de `run_agent` (`rest[-1].role == "tool"`) vaciaría `kept` a `[]` (dejando solo
     `system` sin ningún turno `user`/`assistant`/`tool`). La unidad atómica de protocolo es
     `[assistant(tool_calls=[c1..ck]), tool(c1), ..., tool(ck)]` (y, si es el turno final y excede `budget_tokens`, conviene
     recortar `tool.content` con marcador explícito en copias `dataclasses.replace(...)` para respetar `n_ctx` sin romper el
     emparejamiento `tool_calls` ↔ `tool_result`).

2. **`spike/store/secrets.py:38, 46, 54, 60` (`SecretStore` en modo fallback `file-0600`) — Pérdida silenciosa de secretos
   bajo `-X utf8=0` / locales no UTF-8 y `AttributeError` ante JSON no diccionario:**
   - `_load()` llama a `self.fallback_path.read_text()` sin `encoding="utf-8"` y captura `except (OSError, ValueError): return {}`.
     Como `UnicodeDecodeError` hereda de `ValueError`, si `secrets.json` contiene bytes UTF-8 no ASCII (p. ej. un conector o
     metadato escrito previamente en UTF-8 o `ensure_ascii=False`) y SPIKE se ejecuta bajo `LC_ALL=C python -X utf8=0`,
     `_load()` devuelve silenciosamente `{}`; la siguiente llamada a `store.set("openai", "sk-...")` **sobrescribe
     `secrets.json` borrando las demás claves previas**. En Windows (`cp1252`), `read_text()` corrompe claves UTF-8 en
     mojibake sin lanzar excepción.
   - `_save()` abre el descriptor temporal con `os.fdopen(fd, "w")` sin `encoding="utf-8"`.
   - Si `secrets.json` contiene un JSON válido que no sea objeto (`[]`, `null`, `123`), `_load()` devuelve ese valor y
     `get()`, `set()` o `delete()` fallan con `AttributeError` / `TypeError` no controlados.

### Propuesta técnica para Claude

1. **En `spike/core/context.py` (`fit_messages`):**
   - Agrupar `rest` en unidades indivisibles donde cada `Message(role="assistant", tool_calls=[...])` va unido a todos los
     `Message(role="tool")` contiguos que le siguen (descartando de entrada cualquier `role == "tool"` suelto al inicio de
     `rest`).
   - Recorrer las unidades desde la más reciente hacia atrás; si la unidad más reciente es un bloque
     `[assistant(tool_calls), tool_1, ..., tool_k]` cuyo coste junto a `system` supera `budget_tokens`, conservar el bloque
     completo recortando proporcionalmente el `content` de sus `tool_i` mediante `dataclasses.replace` con sufijo
     `"\n...[tool output truncated to fit context window]"` (y conservando también el `user` inmediatamente anterior si cabe
     o con presupuesto mínimo reservado), de modo que ningún proveedor reciba jamás un `tool` sin su `assistant(tool_calls)`
     ni un `assistant(tool_calls)` al que le falte uno de sus `tool_result`.

2. **En `spike/store/secrets.py` (`SecretStore._load` y `_save`):**
   ```python
   def _load(self) -> dict[str, str]:
       try:
           raw = json.loads(self.fallback_path.read_text(encoding="utf-8"))
       except (OSError, ValueError):
           return {}
       if not isinstance(raw, dict):
           return {}
       return {k: v for k, v in raw.items() if isinstance(k, str) and isinstance(v, str)}

   def _save(self, data: dict[str, str]) -> None:
       self.fallback_path.parent.mkdir(parents=True, exist_ok=True)
       tmp = self.fallback_path.with_suffix(".tmp")
       fd = os.open(tmp, os.O_WRONLY | os.O_CREAT | os.O_TRUNC, 0o600)
       with os.fdopen(fd, "w", encoding="utf-8") as f:
           json.dump(data, f, ensure_ascii=False)
       os.replace(tmp, self.fallback_path)
       os.chmod(self.fallback_path, 0o600)
   ```
