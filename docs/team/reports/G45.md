# Informe G45 — Prueba de humo del instalador sin modelo

## 1. Resumen

`scripts/installer_smoke.py` (solo biblioteca estándar) instala el wheel de la CI en un venv temporal, arranca SPIKE con
`SPIKE_HOME`, `HOME`, `USERPROFILE` y `SPIKE_API_TOKEN` dentro de la carpeta temporal en un puerto libre de loopback,
comprueba `/api/health` y `/v1/models`, comprueba que sin token `/v1/models` da 401, detiene el servidor, borra la carpeta
y afirma que ya no existe y que el `~/.spike` real no cambió (tamaño y mtime de cada archivo).

## 2. Criterios

- [x] Script con la ruta del wheel como argumento (`--wheel`).
- [x] Instalación en venv nuevo con el `venv` del Python en ejecución. Se usa el índice normal para las dependencias
  (decisión honesta: sin red no se pueden resolver; la instalación real funcionó aquí, ver sección 4).
- [x] Arranque con `SPIKE_HOME` temporal y puerto libre; `/api/health` y `/v1/models` verificados. `/v1` exige
  `SPIKE_API_TOKEN` solo si está definido (`spike/server/openai_api.py::check_access`); el script lo define y comprueba
  también el 401 sin clave.
- [x] Parada y desinstalación limpia con aserciones.
- [x] Paso en el trabajo `package` de `.github/workflows/ci.yml`, tras el paso que construye e instala el wheel.
- [x] Documentado en `docs/guide/en/installation.md` y `docs/guide/es/installation.md` (qué cubre y qué no).
- [x] Pruebas unitarias en `tests/test_installer_smoke_g45.py`.
- [x] `--use-python` añadido (documentado) para probar solo arranque/comprobación/parada/limpieza con un intérprete que ya
  tiene SPIKE.

## 3. Decisiones

- No hace falta ningún GGUF ni proveedor falso: el servidor se arranca con `--no-local` y `/v1/models` lista `spike-auto`,
  los especialistas y los proveedores configurados sin cargar nada.
- No se usa `spike.launcher` (el lanzador de escritorio): elige un puerto aleatorio, abre una ventana o el navegador y no
  se puede dirigir sin interfaz. Se arranca `spike.cli.main(["serve", "--no-local", "--port", N])`, el mismo servidor
  FastAPI/uvicorn. La ventana nativa y los instaladores de escritorio no quedan cubiertos.
- El entorno del hijo elimina las variables `SPIKE_*` heredadas; pip usa `--no-cache-dir` para no escribir en el home real.
- Las llamadas HTTP ignoran los proxies del entorno (`ProxyHandler({})`).
- Se comprueba además que el servidor escribió algo bajo `SPIKE_HOME` (si no, corrió contra otra carpeta).

## 5. Qué no se hace

- No sustituye a I3 (instalador en máquinas reales); no prueba instaladores de escritorio firmados, la ventana nativa
  ni un modelo real. Solo Linux medido; en Windows/macOS el script usa rutas `Scripts/python.exe`/`bin/python` pero no se
  ha ejecutado allí. El paso de CI no se ha ejecutado en GitHub (no se empuja).
- La aserción del home real solo cubre `~/.spike`, no otras rutas (p. ej. cachés).
