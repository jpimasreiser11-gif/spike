# G9: Fiabilidad determinista de Dependency Doctor y Visual Critic (`diagnostics.py` y `visual_checks.js`)

## Resumen

En el ámbito de mejoras acotadas de diagnósticos, accesibilidad y pruebas (Secciones 2, 6 y 10 de incorporación), se
identificaron y corrigieron seis defectos reproducibles en la ejecución local de **Dependency Doctor** y **Visual Critic**
(`spike/dev/diagnostics.py` y `spike/dev/visual_checks.js`), manteniendo intactos los permisos (`ask` / `once=True`), el
aislamiento `Sandbox`, la expresión regular estricta de pines `==` y el contrato `DiagnosticUi`:

1. **Fallo con UTF-8 BOM (`\ufeff`), espacios en licencias, objetos legacy `{"type": ...}` y entradas nulas en
   `license_report()`:** un `package-lock.json` guardado con BOM UTF-8 (habitual en Windows PowerShell / editores)
   lanzaba `JSONDecodeError` y devolvía `status: 'error'` para todo el proyecto; licencias con espacios (`" MIT "`) se
   marcaban erróneamente como `'review'`; cadenas en blanco (`"   "`) se marcaban como `{'license': '   ', 'status': 'review'}`
   en vez de `'unknown'`; objetos npm heredados `{"type": "Apache-2.0"}` producían `{'license': '', 'status': 'review'}`; y
   una entrada malformada `null` en `packages` lanzaba `AttributeError` abortando el resto de paquetes. Ahora se lee con
   `encoding='utf-8-sig'` y `_normalize_license()` normaliza cada entrada sin perder el carácter conservador de la lista
   blanca (`LICENSES`).
2. **`requirements.txt` con BOM UTF-8, salidas CRLF (`\r\n`) y argumento `path` no textual en `DependencyDoctor.run()`:**
   un `requirements.txt` con BOM en la primera línea (`\ufeffdemo==1.0.0`) fallaba `re.fullmatch(...)` y devolvía
   falsamente `'unsupported_requirements'`; salidas con `\r\n` dejaban `first = 'exit code 0\r'` provocando `'error'`; y
   valores no textuales en `args['path']` (`['..']`, `123`) se convertían mediante `str(...)` en vez de rechazarse como
   carpeta inválida. Ahora `requirements.txt` se lee con `utf-8-sig` (conservando intacta la regex estricta de pines),
   `first.strip()` tolera CRLF y `path` exige `str | None`.
3. **Salidas MCP de `browser_evaluate` con CRLF, bloques ```` ```json ```` o preámbulo en `VisualCritic.run()`:**
   `result.text.removeprefix('### Result\n').split('\n### ')[0]` fallaba con `JSONDecodeError` si Playwright MCP emitía
   saltos `\r\n`, envolvía el JSON en bloques Markdown ```` ```json ... ``` ```` o anteponía una línea antes de
   `### Result`. `_extract_mcp_json()` normaliza ambos casos sin relajar la validación de esquema.
4. **Falsos positivos de `'overflow'` horizontal dentro de contenedores desplazables acotados (`overflow-x: auto|scroll|hidden|clip`):**
   en `visual_checks.js`, cualquier celda `<td>` o línea `<pre>` dentro de un `.table-wrap` con `overflow-x: auto` que
   cabía perfectamente dentro del viewport se reportaba como desbordamiento horizontal de página porque
   `getBoundingClientRect().right` excedía `clientWidth`. `clippedX()` comprueba si un ancestro recorta `overflowX` y
   permanece dentro de `[-1, clientWidth + 1]`, manteniendo la detección cuando el propio contenedor o un elemento
   externo se sale de la pantalla.
5. **Falsos positivos de `'tap'` (`< 24 px`) y `'contrast'` en etiquetas `.sr-only` recortadas a `1×1 px`:** elementos
   visualmente ocultos para lector de pantalla (`width <= 1`, `height <= 1`, `overflow: hidden` y `clip` / `clip-path`)
   pasaban la guarda `!rect.width` (`1 !== 0`) y recibían falsos avisos visuales de tamaño táctil y contraste. Ahora se
   siguen auditando sus nombres accesibles (`label`/`alt`), pero se omiten las comprobaciones puramente visuales (`tap`,
   `overflow`, `contrast`).
6. **Iconos `<svg aria-label="...">` en botones/enlaces y alfa porcentual CSS Color 4 (`rgb(... / 10%)`) en
   `visual_checks.js`:** `name(el)` ahora reconoce descendientes con `aria-label` no ocultos (`:not([aria-hidden="true"])`)
   además de `img[alt]`, y `rgba()` parsea porcentajes tanto en canales RGB como en canal alfa (`10%` → `0.1`).

Verificado con TDD en `pytest` (incluyendo ejecución real offline en Chromium mediante `SPIKE_CHROMIUM`), modo UTF-8
desactivado (`LC_ALL=C LANG=C python -X utf8=0`), suite completa de Vitest (`web/src/visualChecks.test.ts`) y
`npm run build`. No medido con pesos reales.

## Decisiones

- **Seguridad conservadora intacta:** `utf-8-sig` solo retira un posible BOM inicial `\ufeff`; cualquier directiva `-r`,
  URL `@`, editable `-e`, `--index-url` o rango `>=` sigue rechazándose con `'unsupported_requirements'` sin invocar
  `pip`. En `license_report`, cualquier licencia vacía, no textual o fuera de `LICENSES` sigue quedando en `'unknown'` o
  `'review'`, nunca en `'allowed'`.
- **`.sr-only` auditado para lectores de pantalla pero no para geometría visual:** la guarda `srClipped` se aplica
  *después* de comprobar `alt` y `label`, de modo que un `<input class="sr-only">` sin etiqueta sigue detectándose como
  error `'label'`, pero un botón/enlace `.sr-only` etiquetado no genera falso `'tap'`.
