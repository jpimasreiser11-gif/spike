# G38: command-line help

Done by Claude on the Mac (Argon's quota ran out before this task). Branch `claude/g38`, from main `bd23342` with
`claude/o4-security` merged in (its new `serve --allow-network` option has to be in the reference too).

- 24 options had no help (`serve --host/--port`, `doctor --model/--context/--json`, `models action/--quant`, every
  `chat` option, `bench --repeats/--threads/--kv/--port`, `evolve action/--json`, `forge action`, `adapters
  action/--specialist`, the `paths` of `skills|connectors validate`, `skills list|install --lang`). All have it now,
  written from what each option really does in the code (defaults read from the parser and the functions it calls).
- `scripts/cli_reference.py` writes `docs/guide/{en,es}/cli.md` from the parser: a section per command with a table of
  options, defaults and help, plus real examples. It builds the tables from the parser's actions, not from argparse's
  formatted help, so the output does not change between Python versions or terminal widths. `--check` runs in CI next to
  `compat_matrix.py --check`.
- The help text stays in English, as the rest of the CLI (skills and connectors already give it in both languages); the
  Spanish page says so and has its own introduction and examples.
- `tests/test_cli_help.py`: fails if any command or option has no help, if the walk misses a top-level command, if a
  page is stale, or if a page lacks a command. 4 passed, also under `-X utf8=0`; the guide's G19 tests still pass.

Not done: the spec names `dev` and `render` commands; the CLI has no such commands (Spike Dev and rendering live in the
app), so there is nothing to document for them.
