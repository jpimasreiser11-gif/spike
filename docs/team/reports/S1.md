# S1: Rescatar Studio en los módulos existentes

## Resumen

Se comparó el Studio original, leído exclusivamente en `/Users/jpima/Downloads/Spike`, con `codex/s1`
(base `e263d1308f63a00c7fa13a7a2a36c15b4cbfffdf`). Se rescataron cuatro contratos en las implementaciones actuales:

proyectos, memoria, skills, MCP o API. Los mensajes nuevos tienen traducción es/en en `web/src/i18n.ts` y pasan por
`ApiError`. `docs/STUDIO.md` describe solo lo integrado. El resto del Studio se compara y se deja identificado abajo;
este cambio no promete paridad completa con aquella implementación.

## Decisiones

- Rescate selectivo en módulos existentes, sin copiar `Studio`, `WorkEngine`, sus tablas o sus rutas `/api/projects`/`/v1`.
  A9 ya tiene la cola y ramas/versiones de proyecto; A1/A11 tienen validación y ampliación de skills. Las diferencias
  de local-only y aceptación de modelos necesitan la política del líder; no se declara que main ya las cubra.
- ZIP v1 ampliado de forma aditiva con notas opcionales. No se importa automáticamente el JSON antiguo porque también
  contiene una preferencia local-only que la app actual no podría respetar al convertirlo. No se migra estado privado
  del propietario ni se abren sus bases SQLite.
- Texto original escrito para esta integración; no se copian recursos upstream, scripts, marcas ni assets.
  No hacen falta nuevas atribuciones ni dependencias. Sin nuevas rutas ni componentes de producto.
- Los source/meta/IDs de memoria no son datos portables: se transportan solo kind/text. Archivos indexados se
  reindexan como antes; resúmenes de conversación se excluyen de las notas. Orden estable por kind/text.
- Los helpers admiten MemoryStore opcional para compatibilidad con llamadas existentes; si un import tiene notas
  y el caller no entrega MemoryStore, se rechaza en lugar de perderlas. La ruta HTTP siempre lo entrega.
- La contención de archivos rechaza symlinks incluso internos: la representación portable contiene archivos propios,
  no referencias dependientes del sistema local. No pretende resolver carreras contra procesos locales hostiles.
- `usage: null` distingue desconocido de cero real. La API suma solo pares válidos de enteros no negativos;
  los contadores estimados del log de facturación no se presentan como uso medido del backend.
- No se cambian tests existentes para ocultar fallos del sandbox. La suite general no puede abrir puertos y psutil
  encuentra sysctl restringido. Se excluyeron explícitamente módulos/tests conocidos de runtime real; la ejecución
  del intento anterior encontró pruebas reales adicionales en fix_forgetting y tune: fallaron antes de arrancar un
  motor (bind/log rechazados). Esta continuación las excluye explícitamente antes de repetir el conjunto general.
  No se entrenaron modelos ni se descargaron pesos.
