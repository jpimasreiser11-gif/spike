# O3: Instalar skills desde una URL de GitHub, con revisión / Install skills from a GitHub URL, with review

## Resumen
Settings › Skills tiene ahora un bloque "Instalar una skill desde GitHub": pegas una URL, SPIKE descarga el ZIP de
`codeload.github.com` (sin git, sin ejecutar nada), lo valida en memoria y muestra licencia, SKILL.md y todos los archivos
(texto de los de texto, marca "binario" en los demás). Solo entonces un segundo botón instala exactamente lo revisado
(referenciado por `preview_id` + SHA-256), con la skill DESACTIVADA; se activa con el interruptor existente.
Nada lo puede llamar un modelo.

## Criterios
- URLs `https://github.com/<owner>/<repo>` y `.../tree/<ref>/<path>`; look-alikes, credenciales, puerto, query, `%`, `..`: met (`test_non_github_and_odd_urls_are_refused_before_any_request`, 29 casos, y ninguna petición sale).
- ZIP de codeload, sin git/scripts; límites de descarga (25 MiB), total descomprimido (8 MiB), 200 ficheros, 2 MiB por fichero, ratio 250:1: met (`test_zip_bomb_by_size_and_by_ratio`, `test_limits_on_count_total_and_download`, `test_download_without_content_length_is_cut_at_the_limit`). Los bytes se cuentan al descomprimir, no se fían de las cabeceras.
- `../`, rutas absolutas, `\`, `:`: se rechaza todo el ZIP (`test_unsafe_paths_refuse_the_whole_archive`); symlinks dentro de la skill: rechazo (`test_symlink_entries_are_refused`).
- Validador existente (`validate_skills`) sobre una copia temporal; la regla `license` se ignora y se usa la lista propia: met (`test_validator_problems_block_the_install`).
- Licencia (frontmatter SPDX, LICENSE de la skill, LICENSE del repo): solo MIT, Apache-2.0, BSD-2/3-Clause, ISC se pueden instalar/activar; GPL, desconocida o ausente: visibles en la previsualización, instalación rechazada 403 `license_blocked` (`test_license_detection`, 15 casos).
- Previsualización sin escribir nada; instalación con segundo request: met (`test_happy_path_...`: el árbol de `SPIKE_HOME` es idéntico tras el preview, y la instalación no vuelve a descargar). Hash/preview_id manipulado: 400 `hash_mismatch`, 404 `preview_expired`; el preview es de un solo uso (`test_preview_id_and_hash_tampering_is_refused`).
- Instalada desactivada: met (entra en `disabled_skills` antes de mover la carpeta; `GET /api/skills` da `enabled: false`; el interruptor existente la activa).
- Solo este ordenador: met, reutiliza `local_only` de `backup_api` (loopback, Origin, `application/json`); se comprueba antes de leer el cuerpo (`test_requests_from_another_machine_or_site_are_refused`).
- Ninguna herramienta de modelo lo alcanza: met (`test_no_model_tool_can_reach_the_import`: solo `server/app.py` importa los módulos, una sola línea de `include_router`, `/v1` y `/mcp` no lo exponen).
- Salida HTTP normal: `httpx.AsyncClient(trust_env=True)` (respeta HTTP(S)_PROXY/NO_PROXY), test `test_downloader_uses_the_environment_proxy_settings`. Redirecciones: solo al mismo host de descarga (`test_redirects_stay_on_the_same_host`).
- UI es/en en `web/src/i18n.ts` (`skillImport`), componente nuevo `SkillImport.tsx` con su `SkillImport.css`; SKILL.md y archivos se muestran como texto plano (no se usa Markdown: no se renderiza nada del repositorio).
- Rechazo en modo sin red/offline: NO hecho, porque en esta base de código no existe tal modo (grep de offline/no-network/allow_network en `spike/` no encuentra un ajuste de la app; `--allow-network` de la CLI es sobre el bind del servidor). Sin conexión, la descarga falla con `network` (502) y un mensaje claro.

## Decisiones
- Un único módulo de lógica `spike/skills/github_import.py` y el router `spike/server/skill_import_api.py` (una línea en `app.py`).
- "Visible pero bloqueada": interpretado como visible en la revisión (licencia, SKILL.md, archivos) y NO instalable; así nunca hay que tocar el interruptor ni el endpoint `PUT /api/skills/{name}` para impedir activar una skill con licencia no permitida. Pregunta abajo.
- Si el frontmatter y un LICENSE contradicen, gana la lectura más estricta. El LICENSE del repo solo se mira si la skill no declara ninguna.
- Ramas con `/` en `/tree/<ref>/…` no están soportadas (ambiguas sin consultar la API); se usa `HEAD` si no hay ref.
- Un nombre ya existente (también uno incluido) nunca se reemplaza (409), porque las skills de usuario sobrescriben a las incluidas.
- Las previsualizaciones viven en memoria del servidor (máx. 5, 15 min, un solo uso). Si el servidor se reinicia hay que volver a revisar.
- Instalación: carpeta preparada junto a `skills/` y movida con un único `rename`.
- `GET /api/skills` / reload: tras instalar se llama a `skills.reload()`.

## No hecho / no medido
- No se probó contra GitHub real (sin red en tests): que `https://codeload.github.com/<o>/<r>/zip/HEAD` funcione para HEAD no está medido.
- No existe modo offline en la app que rechazar (ver arriba).
- `docs/api` describe el cuerpo de las dos rutas según el esquema pydantic; las rutas siguen sin tipo de respuesta detallado.
- Las rutas guardan el estado de previsualización en memoria de un proceso (no multi-worker).
