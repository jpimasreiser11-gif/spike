# A1: Paquete de skills y validadores

## Resumen

Se incluyen nueve perfiles originales Apache-2.0 en formato Agent Skills: decision-simulator (business),
test-inventor, migration-architect y performance-profiler (code), localization (writing), experiment-designer
(science), synthetic-data (data), vector-designer (design y writing) y system-diagnostic (core). Se seleccionan
con consultas es/en y respetan los permisos existentes. Los comandos `spike skills validate [PATH...]` y
`spike connectors validate [FILE]` validan sin red ni ejecución de herramientas y devuelven 1 ante problemas.
CI incorpora ambos comandos en toda la matriz Python. El panel muestra descripciones es/en desde i18n.ts;
las descripciones de skills del usuario conservan su texto. A1 pasa sus pruebas enfocadas y las pruebas/build web;
la suite Python completa encuentra restricciones del sandbox detalladas abajo. No se ha hecho commit ni push.

## Criterios

- met: cada uno de los nueve perfiles se selecciona primero para dos consultas españolas y dos inglesas y no
  para una consulta ajena: `test_new_skills_route_in_both_languages` (36 selecciones positivas, nueve negativas;
  también prueba vector-designer en writing).
- met: pruebas por clase de fallo: formato/front matter/codificación/lectura, licencia, herramientas, cuerpo,
  secretos y recursos; para conectores también campos obligatorios, transporte, versiones, referencias env,
  argumentos sensibles e identificadores duplicados. Véanse `test_skill_validation_failures`,
  `test_skill_validation_input_errors`, `test_connector_validation_failures`, `test_connector_bad_files`,
  `test_connector_duplicate_ids`, `test_connector_rejects_version_ranges`,
  `test_connector_rejects_literal_secret_arguments` y `test_download_launchers_need_pins_on_all_platforms`.
- met (configuración local): CI ejecuta ambos validadores sobre el conjunto incluido:
  `test_bundled_validators_and_ci`, `.github/workflows/ci.yml`. No se ha lanzado una ejecución remota de CI.
- met: mensajes CLI en es/en (`--lang es|en`), descripciones del panel en `web/src/i18n.ts`, componente nuevo
  `SkillDescription.tsx`, pruebas de traducción y respeto de overrides en `web/src/skills.test.tsx`.

## Decisiones

- Los validadores son módulos separados del cargador permisivo de perfiles del usuario. El cargador ahora
  convierte cabeceras que no son mapas y metadatos de routing escalares incorrectos en SkillError, sin
  AttributeError/TypeError. No se cambia el algoritmo del router ni se añaden servicios, rutas o permisos.
- Skills: se reutilizan las reglas del loader para nombre, carpeta, descripción y licencia inferida desde
  LICENSE. `allowed-tools` admite lista o texto separado por espacios/comas y exige nombres de herramientas
  Tool existentes, descubiertos mediante AST sin instanciar servicios ni importar dependencias opcionales.
  El cuerpo debe tener entre 1 y 60 000 caracteres no vacíos, coherente con el límite de carga existente.
  Se detectan formatos comunes de claves, claves privadas y asignaciones sospechosas, también en recursos;
  no se imprimen los valores detectados. Se rechazan recursos enlazados fuera de la carpeta. La detección
  es heurística, no una garantía de ausencia de secretos. Se reconoce el placeholder explícito
  `your_api_key_here` usado por documentación upstream sin modificar esos archivos.
- Licencias aceptadas: MIT, Apache-2.0, BSD/BSD-2-Clause/BSD-3-Clause, ISC, CC0/CC0-1.0 y CC-BY/CC-BY-4.0.
  El catálogo existente conserva sus declaraciones MIT con aclaración Apache y su licencia propietaria
  explícita para un CLI ya instalado, no redistribuido. Esta última no permite descarga mediante npx/uvx.
- Conectores: se exigen id/nombre/descripción/licencia/source/transporte y campos de ejecución del transporte.
  URLs HTTPS sin credenciales y sin parámetros de consulta sensibles; transporte stdio o http.
  Los paquetes descargados con npx/uvx requieren versión exacta de tres componentes (también launchers
  .cmd/.exe y rutas absolutas). No se atribuye una versión ficticia a endpoints alojados ni ejecutables
  preinstalados. Se rechazan flags que incorporan paquetes adicionales fuera de esta forma de pin.
- Los secretos del catálogo son declaraciones con nombre de entorno, etiqueta/URL/opcional; las referencias
  deben declararse. Se permiten `{workspace}` y `{data}` para valores no sensibles. Credenciales en headers/env
  deben referenciar nombres declarados; se admiten `{NAME}` y `Bearer {NAME}`. No se permiten argumentos
  --token/--password/--secret/--api-key: se deben proporcionar mediante entorno. No se leen valores del entorno.
- Los skills son instrucciones, no nuevos ejecutores: cProfile es estándar; Faker solo se usa si ya existe,
  con alternativa estándar; localization consulta el glosario presente; SVG usa el panel de artefactos
  existente. system-diagnostic pide `spike doctor --json` y solicita salida pegada si no dispone de una
  herramienta de comandos autorizada. No evade permisos con otra herramienta. Datos sintéticos son fixtures,
  nunca texto para el corpus de entrenamiento.
- Se extendió el listado esperado de skills existente y el smoke de Skills para comprobar nueve tarjetas
  habilitadas y la descripción española de localization. Sin dependencias nuevas ni cambios del tablero.
