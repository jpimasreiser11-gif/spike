# A5: Dependency Doctor y Visual Critic

## Resumen

Dependency Doctor y Visual Critic están disponibles como herramientas en `spike dev` y en los chats Core/Code,
incluidos proyectos. Cada ejecución pide permiso de una sola vez, incluso con una política de sesión permisiva.
Dependency Doctor detecta ejecutables instalados mediante `shutil.which`, usa el ejecutor y sandbox existentes,
audita requisitos Python fijados o un lock npm y combina el resultado con metadatos locales de licencias.
Visual Critic reutiliza la conexión Playwright de View ya abierta, ejecuta comprobaciones originales y devuelve
selectores y una captura inline. Una tarjeta nueva abre ambos informes en el panel de artefactos aislado, con
textos es/en y escape de contenido externo. Sin instalaciones, dependencias nuevas, commits ni push.

## Criterios

- **met** — fake pip-audit binary test: `tests/test_dev_diagnostics.py::test_fake_pip_audit_binary_merges_licenses`.
  Ejecuta un binario temporal real que registra argumentos y devuelve una vulnerabilidad con código de salida 1;
  comprueba el informe combinado, el permiso obligatorio y que no se ejecuta al construir la herramienta.
- **met en fixture DOM; Chromium pendiente de validación** — visual critic finds each planted issue in a fixture page:
  `web/src/visualChecks.test.ts`, primer test, ejecuta el mismo JavaScript enviado a View y encuentra contraste,
  imagen sin alt, control sin nombre, desbordamiento y objetivo menor de 24 px. El DOM es jsdom y las coordenadas
  de layout son explícitas. El segundo test comprueba luminancia, alfa, texto grande/negrita, etiquetas y fondos
  complejos. `tests/test_dev_diagnostics.py::test_critic_finds_every_planted_issue_offline` añade la fixture en
  Playwright real, sin peticiones de página; no se pudo completar en este sandbox (ver Pendiente).
- **met** — permisos, denegación/headless sin ejecución, ausencia de auditores, errores/JSON inválido, resultados
  npm, subcarpetas confinadas, requisitos inseguros, licencias desconocidas y symlink externo:
  `tests/test_dev_diagnostics.py`.
- **met con cliente MCP falso** — conexión View existente, captura y selectores, conector bloqueado, errores MCP y
  captura ausente: `test_critic_reuses_running_view_and_returns_screenshot` y
  `test_critic_reports_mcp_failure_missing_screenshot_and_respects_blocked_connector`.
- **met** — componente nuevo, informe HTML escapado y apertura mediante ArtifactContext:
  `web/src/diagnostics.test.tsx`; compilación TypeScript/Vite aprobada.

## Decisiones

- No se añaden rutas HTTP: se usa el flujo de herramientas/permisos/resultados existente. La integración fuera de
  `spike/dev/` se limita al registro por workspace/proyecto, catálogo Core/Code, presentación, traducciones y tests.
- Visual Critic inspecciona la página actual; no navega, arranca conectores ni crea un navegador diferente de View.
  Evalúa el DOM visible principal. La captura se toma después: el informe indica que la página puede cambiar.
- Contraste de colores computados sólidos: luminancia WCAG 2.1, composición alfa y umbrales 4,5:1 / 3:1 para texto
  grande. Fondos con imágenes/gradientes, filtros, opacidad y colores no interpretables quedan como no evaluados.
  Iframes/shadow DOM y excepciones de tamaño de objetivos no están cubiertos; no se anuncia certificación WCAG.
- En esta rama no existe un verificador de licencias de dependencias que se pueda invocar. Se reutiliza la lista
  `spike.runtime.models.ALLOWED_LICENSES`, añadiendo BSD-2-Clause e ISC, para revisar identificadores exactos del
  lock npm. SPDX compuestos o licencias fuera de la lista requieren revisión. Requisitos Python sin metadatos se
  muestran como desconocidos; no se consultan registros ni se declara compatibilidad legal.
- Python admite `requirements.txt` con versiones exactas, sin rutas, inclusiones, editables, URL ni opciones de
  índice. Usa `--no-deps --disable-pip` para no instalar ni ejecutar la resolución de pip; solo revisa las versiones
  enumeradas, sin resolver transitivas. Esto se explica en el informe. Flags contrastados con la documentación
  primaria: https://github.com/pypa/pip-audit/blob/main/README.md#usage . No se ha hecho una auditoría de registro real.
- npm usa `audit --json --ignore-scripts --package-lock-only`, nunca `fix` ni instalaciones. Se distinguen hallazgos,
  herramienta ausente, falta de manifiesto, requisitos no admitidos y error; un error no se muestra como auditoría limpia.
- Resultados marcados privados como el contenido de archivos. La captura está en datos UI, no en el texto enviado
  al modelo. No se registran stderr ni errores remotos crudos en el informe. No se han medido modelos/pesos reales.
