# G39: Sample projects

## Summary
Six bundled sample projects, each in Spanish and English: expense sheet (Analytics), report brief (Creator), mini web
page (Dev), long handbook (memory and search), a Workflows flow, and a paper-mode Finance case. Files live as plain
files in `spike/samples/data/<id>/{sample.json,es/,en/}` (shipped automatically: hatch `packages = ["spike"]` includes
the whole package folder, same as the bundled skills). `spike.samples.build_archive` packs one language into a normal
`spike-project` archive and the route imports it with the existing `import_project` (one code path).
New router `spike/server/samples_api.py` (`GET /api/samples?lang=`, `POST /api/samples/{id}/import?lang=`), one line in
`app.py`. UI: new `SampleProjects.tsx` dialog, opened from a sparkle button in the Projects header (es/en texts).
The UI sends its language; the server falls back to English for an unknown one.

## Criteria
- [x] Six samples, es and en, all content written by me, invented, no brands, no personal data.
- [x] Uses the existing project import format; own APIRouter; UI entry with one-click import.
- [x] Tests: each sample imports (both languages), files load, CSV parses (40 rows), workflow validates with the real
  validator (`/api/workflows/validate`), finance case is paper only, size limits, 404; vitest for the UI.
- [x] Smoke step: imports the expenses sample over the API and checks its CSV (`web/e2e/smoke.mjs`).
- [x] Total size under 200 kB.

## Decisions
- Handbook is 3,663 words (en) and 3,542 (es) by `wc -w`, above the "~3,000" target; I kept it rather than cutting
  sections, and the test accepts 2,700 to 4,200.
- Finance: project mode `finance`, instructions name only `paper_order`; a `rule` note says never `propose_live_order`.
  The test fails if that tool name appears on any line that does not also say never/nunca. Prices are an invented
  seeded random walk (60 sessions), not market data.
- The workflow is stored where the store reads it (`workflows/wf-sample-review/0001.json`) with its CSV beside it.
  Not run end to end (needs a model); only validated.
- The smoke step uses the API, not the dialog, so later smoke steps keep their selected project.
