# A11: Marketplace local y 30 skills incluidas

## Resumen

El marketplace mínimo permite listar un índice JSON local elegido por el usuario e instalar sus paquetes ZIP mediante
`spike skills list` y `spike skills install`. Exige licencia permitida, SHA-256 correcto, rutas dentro del proyecto,
validación offline de todas las skills y permiso explícito de escritura (`--yes`). No reemplaza skills existentes ni
ejecuta los recursos del paquete. Se añaden nueve perfiles originales Apache-2.0 para llegar a 30, con routing es/en
para cada uno de los 30. Landing page, informe, deck, dashboard y aplicación de datos incluyen `template.md` reutilizable.
Las nueve descripciones nuevas están traducidas en `web/src/i18n.ts`. Guía bilingüe: `spike/skills/MARKETPLACE.md`.

## Criterios

- **met — hash mismatch refused:** `tests/test_skill_marketplace.py::test_hash_mismatch_refused_without_writing`
  comprueba el rechazo antes de crear el destino.
- **met — ≥30 bundled skills pass validate:** `tests/test_skill_catalog.py::test_catalog_count_validation_and_routing_coverage`
  confirma 30 perfiles, cobertura completa y cero incidencias; `spike skills validate` devuelve `Validation passed`.
- **met — cada skill tiene routing:** `test_every_bundled_skill_routes_in_spanish_and_english`, 30 casos parametrizados,
  cada uno con una petición es y otra en. Conservadas también las pruebas de routing anteriores.
- **met — plantillas de creación:** `test_creator_templates_are_loadable_resources`, cinco casos; `web/src/skills.test.tsx`
  verifica sus traducciones y renderizado. Las plantillas se leen con el mecanismo existente de recursos de skills.
- **met — tests first:** antes de implementar, marketplace falló al importar el módulo ausente; catálogo obtuvo
  `15 failed, 21 passed`, incluidos el límite de 30, los nueve routings nuevos y los cinco recursos ausentes.

## Decisiones

- Se elige la alternativa de **índice local** de la especificación. No se añaden transporte git, catálogo remoto,
  configuración remota persistente, rutas HTTP ni interfaz nueva. Un usuario puede descargar un repositorio y elegir
  su índice local. La CLI existente recibe dos acciones; el resto del marketplace vive en `spike/skills/marketplace.py`.
- Cada entrada exige exactamente `id`, `license`, `sha256`, `path`; cada paquete contiene carpetas de skills en la raíz
  y una licencia homogénea que coincide con el índice. Índice y ZIPs son entradas explícitas, sin catálogo por defecto.
- Destino explícito dentro del directorio actual. Para cargarlo en la app se usa `skills` de un `SPIKE_HOME` local al
  proyecto; una app ya iniciada requiere reiniciarse. Esto evita escribir en la instalación personal del propietario.
- La extracción tiene límites de bytes y entradas, rechaza enlaces ZIP, rutas ascendentes y recursos con posibles
  secretos; valida todo antes de publicar y revierte sus carpetas nuevas si falla la publicación. No modifica el
  importador de paquetes existente, cuyo comportamiento permisivo anterior permanece fuera de esta tarea.
- Perfiles adicionales: `release-notes`, `incident-review`, `dataset-audit`, `api-contract`. Son instrucciones originales,
  no datos de entrenamiento ni capacidades medidas con pesos reales. No se añaden dependencias ni contenido adaptado.
