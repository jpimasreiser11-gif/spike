# A3: Analytics: contratos, SQL Guardian, rescate, linaje y previsiones

## Resumen

Analytics rescata CSV antes de cargarlos, valida contratos locales JSON/YAML y devuelve infracciones estructuradas;
SQL Guardian analiza una sola sentencia con el parser de DuckDB, ejecuta consultas en transacciones de solo lectura,
limita las vistas previas y explica el plan sin modelos, con opción de EXPLAIN sin ejecución. Añade cinco previsores
base y selección por MAE con backtest temporal común. Las herramientas devuelven el linaje y la interfaz muestra el
antes/después, plan, pasos y tabla de backtest en español e inglés. Una prueba de chat con proveedor simulado verifica
el linaje dentro del ZIP de prueba real. Implementado en `codex/a3`, pendiente de revisión de Claude; sin commit/push,
sin dependencias nuevas y sin modificar el tablero, STATUS ni CHANGELOG.

## Criterios

- **met** — forecast methods tested against hand-computed values: `test_baselines_by_hand` comprueba naive, seasonal
  naive, drift, SES y Holt; `test_holt_and_seasonal_cycle_by_hand` añade tendencia no lineal y repetición estacional;
  `test_rolling_origin_uses_only_past_and_same_folds` comprueba MAE, errores, ventanas y selección sin fuga temporal.
- **met** — SQL Guardian refuses writes without approval: `test_guardian_refuses_writes` cubre DELETE/DROP/CREATE,
  sentencias múltiples, COPY y EXPLAIN ANALYZE DELETE; `test_guardian_blocks_side_effects_even_in_select_and_explicit_approval_is_exact`
  comprueba nextval en SELECT, aprobación booleana exacta y bloqueo de COPY incluso aprobado;
  `test_contract_report_is_visible_and_model_cannot_approve_sql` prueba que un argumento del modelo no autoriza escritura.
- **met** — rescue fixes a messy CSV fixture and reports each fix: `test_messy_csv_fixes_are_reported` usa una fixture
  cp1252 con preámbulo, punto y coma, coma decimal, fechas españolas, duplicado y columna vacía; comprueba filas,
  suma 30,75, cada reparación, dimensiones y checksum, manteniendo intacto el original.

## Decisiones

- Módulos nuevos en `spike/analytics/`: `contracts.py`, `rescue.py`, `guardian.py`, `forecast.py`, con contratos y límites
  documentados en `spike/analytics/README.md`. Se conservan los cargadores existentes para formatos distintos de CSV.
- El DuckDB en memoria necesita escritura durante la carga de confianza. Después, cada consulta predeterminada usa
  `BEGIN TRANSACTION READ ONLY`, además del bloqueo existente de acceso externo y configuración. No se abre una base
  persistente modificable. Una carga fallida no puede consultarse.
- Las escrituras aprobadas solo están disponibles para un llamador Python de confianza mediante
  `Session.query(..., approved=True)` y solo afectan tablas efímeras. Obtener la aprobación humana corresponde a ese
  llamador. El chat continúa de solo lectura: no hay bandera de aprobación en esquemas de herramientas ni nueva ruta
  para escribir archivos. Se prueba que el modelo no puede aprobarse a sí mismo.
- `data_sql(explain_only=true)` y `Session.explain` permiten inspeccionar el plan sin ejecutar la consulta. Las consultas
  normales también explican antes de ejecutar. El LIMIT incluye una fila centinela que solo detecta truncamiento.
- Contratos: columnas requeridas, tipos lógicos, nulabilidad y reglas min/max/enum/unique. Se validan definición y datos
  al cargar, después del rescate; los valores privados no se incluyen en las infracciones. JSON Schema y PyYAML ya eran
  dependencias declaradas. Un nombre de archivo mal escrito o una ruta fuera del workspace no eluden la validación.
- Rescate determinista UTF-8/cp1252, delimitadores comma/semicolon/tab/pipe y fechas es/en; el locale predeterminado es
  español, con opción inglesa explícita. Los casos ambiguos y limitaciones se documentan. Las reparaciones no escriben
  los archivos originales y la eliminación de duplicados se informa.
- SES/Holt usan parámetros fijos 0,5. Se comparan las cinco bases con las mismas ventanas completas, hasta las últimas
  100, horizonte máximo 100 y serie máxima 10000. No se ajustan hiperparámetros ni se inventan intervalos o precisión
  futura. El llamador debe ordenar y regularizar la serie. Desempates en el orden documentado de los métodos.
- Componente nuevo `AnalyticsEvidence.tsx`; solo dos inserciones de componente en las tarjetas existentes. Traducciones
  nuevas en `web/src/i18n.ts`. Se amplía el smoke de la tarjeta de gráfico. No se añaden rutas HTTP.
- Se añade `data_forecast` a la lista del especialista Data en `spike/specialists/catalog.yaml`: la prueba de integración
  falló antes de esa línea, porque registrar una herramienta no la hacía accesible al especialista.
- El linaje usa el payload UI que ya persiste la conversación y exporta `chat.json`; no cambia el formato del paquete
  de prueba. Se registran rescate, carga/checksum, contratos, plan, consultas, gráfico y previsión de análisis exitosos.
- Pruebas primero: se observaron fallos por módulos/componente ausentes, herramienta inaccesible, falta de EXPLAIN puro,
  tipos Decimal, CSV entrecomillado y carga fallida aún consultable; después se implementaron y quedaron verdes.

- No se han medido velocidad/memoria con archivos grandes, precisión en datos de negocio ni compatibilidad en una
  máquina Windows real. Las previsiones son fórmulas puras: no usan pesos; no medido con pesos reales.
