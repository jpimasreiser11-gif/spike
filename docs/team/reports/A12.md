# A12: De un Excel a una app local

## Resumen
Creator convierte tablas CSV UTF-8 o la primera hoja de XLSX en `data-app-<id>/app.html`, dentro del proyecto o workspace seleccionado. El HTML contiene los datos reales, búsqueda y edición de celdas; se abre en el panel de artefactos con el sandbox y CSP existentes, sin acceso a la API ni red. Sus mensajes solo proponen cambios: el host verifica la ventana emisora, solicita una revisión con valores anteriores/nuevos y presenta «Aprobar escritura». El servidor exige aprobación explícita y un recibo de un solo uso vinculado a esos cambios; verifica la huella del original, rechaza conflictos y serializa a un temporal antes de reemplazarlo. Incluye fixture XLSX original con dos hojas y textos es/en en i18n. No hay dependencias nuevas, llamadas a modelos ni descargas.

## Criterios
- **Cumplido en integración end-to-end offline**: `tests/test_data_app.py::test_xlsx_generated_app_end_to_end` carga el fixture, genera la app, ejecuta su JavaScript real en jsdom (dependencia web existente, sin recursos de red), busca, modifica la celda, captura su propuesta, solicita revisión y aprobación, y reabre el XLSX con el nuevo valor. Se ejecuta cuando están disponibles Node y las dependencias web existentes; se omite explícitamente si faltan. Complementado con la integración API: XLSX → HTML persistido → propuesta de edición → original intacto sin aprobación → escritura aprobada → reapertura XLSX con el nuevo número y la segunda hoja conservada: `tests/test_data_app.py::test_xlsx_to_app_edit_approved_write`. Las pruebas React comprueban Creator → panel, rechazo de mensajes de otras ventanas, revisión, descarte y aprobación explícita. **Pendiente ejecutar navegador real**: `web/e2e/data-app.mjs`, incorporado a `web/e2e/smoke.mjs`, ejercita búsqueda, edición en iframe, original intacto antes de aprobar y regeneración desde el XLSX actualizado. El sandbox de esta sesión impide abrir el puerto local del servidor de pruebas.

## Decisiones
- Esta plantilla usa generación determinista y un botón explícito «Crear app local (escribe app.html)», en lugar de pasar datos por un modelo/Forge. Las otras plantillas conservan su flujo. El propósito introducido se usa como título; la app ofrece consulta y edición genéricas, no desarrollo de lógica personalizada. Se conserva el blueprint anterior por compatibilidad de API; el nuevo flujo de Creator utiliza `/api/creator/data-app`.
- Rutas en `spike/server/data_app_api.py`, registradas con una línea en `app.py`; lógica acotada en `spike/data_app.py`; UI nueva en `DataApp.tsx`. El CSP no se amplía y el iframe no recibe ningún token de aprobación.
- Sesiones en memoria: una hora, máximo 32. Reiniciar, caducar o guardar requiere regenerar la app para volver a editar el original. El HTML guardado sigue siendo una consulta y borrador offline; reabrirlo como HTML genérico no otorga acceso de escritura.
- Alcance: tablas rectangulares con primera fila como cabecera, hasta 2000 filas de datos, 100 columnas, 20000 celdas y 2 MiB de entrada; CSV separado por comas, salida UTF-8. Solo edición de celdas, sin añadir filas, alterar cabeceras ni editar fórmulas. Se rechazan prefijos de fórmulas nuevos (se admiten decimales negativos), números no finitos y números XLSX de más de 15 dígitos significativos para evitar redondeo silencioso.
- XLSX reutiliza `openpyxl`, extra opcional ya declarado: ausencia o archivo inválido produce un error controlado. Conservación de hojas/celdas ordinarias comprobada; no se promete conservar características avanzadas no soportadas por openpyxl. La interfaz avisa de esta limitación antes de crear y aprobar.
- No se han medido pesos reales; esta función no necesita un modelo.
