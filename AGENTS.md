# Instructions for coding agents (Codex and others)

SPIKE is built by a team: **Claude leads** (plans, reviews, merges to `main`, trains and measures the models), **Codex
builds** the tasks the board assigns to it, and a Claude session on the owner's Mac runs the training jobs. The plan is
[docs/team/PLAN.md](docs/team/PLAN.md); the tasks and their owners are in [docs/team/tasks.json](docs/team/tasks.json)
(human view: [docs/team/BOARD.md](docs/team/BOARD.md)). Read the plan before your first task.

## How a task flows
1. The worker (`scripts/team/codex_worker.py`) gives you one task: id, spec, acceptance criteria, paths. You are on the
   branch `codex/<id>`, created from `origin/main`.
2. Build it, test-first. Read 2–3 neighbouring modules and their tests before writing; match their style exactly
   (dense docstrings, short comments, ~120-character lines, same naming and idioms).
3. Write your report at `docs/team/reports/<ID>.md` (format below). Do not commit or push: the worker does it.
4. Claude reviews the branch. Either it merges it into `main`, or it writes `docs/team/reviews/<ID>.md` and sets the task
   to `changes`; you then get the same branch back with that review in your prompt.

Never push to `main`, never edit `docs/team/tasks.json`, `docs/team/BOARD.md`, `docs/team/reviews/`, `docs/STATUS.md`
or `CHANGELOG.md` (Claude merges those). Put the text for STATUS and CHANGELOG in your report instead.

## Hard rules
- **No new dependencies**: do not install packages or add runtime or dev dependencies to `pyproject.toml` or
  `web/package.json` unless the task says so. Use the standard library and what is already declared. When a feature
  would use an external program, call it only if the user has it (`shutil.which`), degrade with a clear message, and test
  it with a fake binary.
- **Nothing invented**: never claim speeds, quality or compatibility you did not measure. Docs say what is built and how
  it is tested; "not measured with real weights" when that is the case. Never fake a test result.
- **No network in tests, no paid calls, no telemetry.** Nothing sends user data anywhere without an explicit setting.
- **Training data**: never use text generated by Claude, GPT, Gemini or Llama models; commercial use must be allowed by
  the license; provenance recorded for every source.
- **Licenses**: write original code. Anything adapted must be MIT/Apache-2.0/BSD/ISC compatible and credited in
  `THIRD_PARTY.md`. No other companies' brand names or assets in shipped content.
- **Security**: tools that run code or touch files ask for permission like the existing tools (`spike/tools/`,
  `spike/dev/tools.py`); paths stay inside the workspace or project; no secrets in logs, records or tests.
- **Cross-platform**: Windows CI runs with cp1252, so every `read_text`/`write_text`/`open` passes `encoding="utf-8"`;
  paths written into records use `Path.as_posix()`; no POSIX-only calls without a guard.
- **User-visible strings** in Spanish and English (`web/src/i18n.ts`).
- **Merges stay small**: new HTTP routes in their own module with an `APIRouter`, registered with one line in
  `spike/server/app.py`; new UI in new component files.
- **The owner's Mac**: do not start llama-server, training, model downloads or anything heavy; never write outside your
  worktree. `/Users/jpima/Downloads/Spike` is the owner's folder: read it only when a task says so, never change it.

## Verify before you finish
From the repository root:
```
.venv/bin/ruff check .
.venv/bin/python -m pytest -q
LC_ALL=C LANG=C .venv/bin/python -X utf8=0 -m pytest -q <your new or changed test files>
```
If you touched `web/`: `cd web && npx vitest run && npm run build`, and extend `web/e2e/smoke.mjs` when your change is
user-facing in an area it covers. Every new behaviour has a test that fails without it.

## Report format (`docs/team/reports/<ID>.md`)
```
# <ID>: <title>
## Resumen            one paragraph: what now works
## Criterios          one line per acceptance criterion: met / not met, and the test that proves it
## Decisiones         what you decided differently from the spec and why
## Pendiente          what is left undone
## Tests              the exact last lines of the commands above
## STATUS.md          the exact row(s): | what | how it is tested | command |
## CHANGELOG.md       the exact bullet(s)
## Preguntas para Claude   only if something blocks you; otherwise "Ninguna"
```
